**4) CONCLUSION**

- Côté client, l’affirmation est **vraie**. Tous les appels HTTP réellement déclenchés côté navigateur passent soit par [internalApiClient.js](f:/dev/oc/p7l1/Abricot/frontend/src/services/internalApiClient.js) vers `/api/*`, soit par un `fetch` local vers `/api/*` dans [AuthContext.js](f:/dev/oc/p7l1/Abricot/frontend/src/context/AuthContext.js), [register/page.js](f:/dev/oc/p7l1/Abricot/frontend/src/app/(auth)/register/page.js) et [profile/page.js](f:/dev/oc/p7l1/Abricot/frontend/src/app/(protected)/profile/page.js). Je n’ai trouvé **aucun** composant/page client qui appelle directement le backend externe via [apiClient.js](f:/dev/oc/p7l1/Abricot/frontend/src/services/apiClient.js) ou une URL backend.
- Côté route handlers, l’affirmation est **partiellement vraie**. Les handlers auth `login/register/me/profile/password` passent par [authService.js](f:/dev/oc/p7l1/Abricot/frontend/src/services/authService.js) puis [apiClient.js](f:/dev/oc/p7l1/Abricot/frontend/src/services/apiClient.js). Les handlers `users/projects/tasks/comments` appellent [apiClient.js](f:/dev/oc/p7l1/Abricot/frontend/src/services/apiClient.js) **directement**.
